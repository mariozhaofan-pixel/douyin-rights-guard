# 三平台提交与回执

当前适用于抖音、快手和B站。2026-10-16优化：作者侧全部用用户截图，只登录非作者检索举报账号；抖音/B站走版权侵权流程，快手新任务优先网页普通举报并显式记 `complaint_route: general_report`。普通举报提交和版权投诉提交分别统计。退出范围的平台不再进入提交队列；历史材料和回执保留，不把未提交的旧草稿计为完成。

## 准备具体可审阅的举报包

每个候选一份草稿，包含平台、候选规范 URL/作品 ID/账号 ID、原作名称与链接、实际核验的重合区段或逐点时刻、截图索引、权属证明类型、事实性理由和请求措施。`browser_visual` 截图模式须列明原片/候选四个对应点及至少两个镜头的具体细节，说明未完整观察中间帧，不能写成连续片段已全部核实。仅在表单实际要求时从 `00_private/claimant.json` 读取必要个人信息，不经聊天或控制台回显。平台要求承诺/签名的正文必须让用户知道且确认，不能代造签名；同一具体目标和已展示声明的明确授权直接复用，不因进入最终按钮再次索要相同确认。

资料权限与提交权限分开：登录读取授权不等于提交投诉；“允许测试”不等于允许对未知对象发起真实举报。先检查用户已有授权，用户已明确覆盖指定作品、平台、首批范围内核实搬运的对象及官方渠道时，按实际核验结果列出具体目标和材料，关联该授权后继续，不逐条再问。尚未覆盖的重大事项（如超出作品/平台范围、身份材料新增外发去向、权属或白名单不明）汇总一次询问，继续不受影响对象；不为每个输入框或同一声明另建确认。如果当前 computer-use 工具另外要求动作时确认，则按工具执行。

长期授权可在私密案件中配置：保存用户明确授权的原话或引用、平台、原作/系列范围、可外发材料及接收方、操作范围、有效期限与撤回条件；未说明的边界不自行扩大。后续常规检索、材料准备和范围内已核实目标的投诉复用该记录，将实际候选ID关联到提交授权，避免逐条重复确认。已接受且无实质变化的声明依既有授权处理；若当前工具要求对法律声明作动作时确认，则把具体目标、声明和材料按批次集中交由用户确认，不承诺绕过。用户撤回或缩小范围立即优先于旧授权，保留历史记录。

填写前核实最终 URL、官方页面来源、权利人身份类型、数据去向提示（包括通知被投诉方的可能范围）、附件格式/大小与声明。第三方聚合举报/解析页面不是平台通道。官网确实指向另一个服务域时记录这一来源再操作。不要自动改用邮件发送；官方邮件备用通道先生成邮件草稿，只有用户明确授权发送该邮件时才发送。

**抖音和B站先选择“侵权”，再选择其中的“搬运”**。快手按用户更新的选择优先网页普通举报，不受本段侵权专用入口要求约束；理由和类别须真实适用，普通举报成功不能称作版权投诉受理。先核验实际入口与所选分支的连续关系；直接选择搬运、看到“盗搬稿件举报”标题或打开深链，都不能证明已进入侵权通道。路线未核验时继续查找正确入口，不执行该对象提交；已有目标授权仍可复用，但不能代替路线核验。

`gate --candidate <id>` 通过只代表本地信息满足脚本条件，不验证法律结论、真实用户确认或平台表单完成状态。证据/白名单/目标有变动应重新核查受影响部分。

抖音外部Chrome已实测“视频页举报 → 侵犯权益 → 提示转入批量侵权举报页 → 搬运/抄袭/洗稿”的连续入口。中间弹窗的“提交”只负责打开正式批量表单，后续“开始识别”也不是投诉成功。该正式分支随后已复用对应身份卡、上传4份证明、填写500字内描述，对单条目标提交，官方弹窗显示“已提交”，并提示可在“历史记录”查看进度或继续发起；据此只记提交成功、待审核/处理，审核结论与下架未验证。表单每组对应1条原作和多条侵权链接，可增加举报组；证明图片PNG/JPG/JPEG每张不超过5MB。页面说明全部或部分材料可能转给被举报人，上传前核对必要范围；身份卡可复用，但每组真实原作和逐条重合证据不能互相替代。识别阶段去重或无法识别的链接单独记录，不计为已提交；已有成功回执的同一目标不重复提交。

快手已登录Web视频的“三点更多 → 举报”表单明确提示侵犯权益或盗用作品需到移动端发起并提交更多证据，当前只见普通举报分类。这是2026-10-14对版权举证能力的观察。依2026-10-16用户更新，当前快手优先在该网页普通举报表单选择真实适用类别，填写已核实事实与原作链接，不强求版权专用表单或手机端。成功提示/编号只登记普通举报提交；表单没有身份附件字段则不发送这些资料。没有适用分类或举报受阻时记录原因，再考虑专门渠道，不能改选无关违规。旧版权投诉记录保持原route。

2026-10-14在外部Chrome已核验B站完整路线：目标视频 → 稿件举报 → “侵犯合法权益”分组内“侵犯个人知识产权（盗搬、抄袭）” → 下一步 → 新开的 `role` 页 → 原创本人 → 下一步 → `index` 举证，目标自动带入。核对入口实际生成的作品、作者参数，不硬编码深链或参数；该路线符合先侵权再其中搬运的要求。已读表单包含被投诉链接、原作链接（外站选择“填写链接”）、最多400字描述、图片最多10张，单文件选择器逐张添加。外站原作要求本人视角主页、后台截图，内容管理截图默认复用用户提供的合格材料；此表单目前未要求身份证、姓名、联系方式，不主动上传备用资料。声明涵盖原作者合法权利、材料真实合法有效及相应责任；同一目标与已展示声明的授权不重复索取。

2026-10-16实际点击B站“批量投诉更多”，弹窗显示“批量投诉TA的稿件（最多50个）”，限定同一被举报账号。对于同一UP主多条已核实搬运且原作材料适用的作品，可使用此批量入口；其他情况逐条提交。每条须对应已复核、已获授权的候选，不加入弹窗中未经复核的其他稿件，不跨UP主混批；最终选定清单及平台回执逐项关联，打开批量弹窗不计提交成功。

B站后续表单填写的两项实测经验：原作链接仅用 `fill` 填入曾在提交时提示“请添加原创视频出处”，改为逐字真实键入完整链接并按Tab后，随后正式提交显示了成功页。遇到这一字段错误时先清除旧值，可用当前工具支持的 `pressSequentially` 输入并失焦校验，不要伪造页面状态。上传从显示 `n/10` 的可见方框触发，隐藏file input不可直接点击；每次只选一个文件，等“图片上传中”消失且计数稳定再继续。只有明确字段校验失败、未送达时才修正后提交；结果不明仍按 `unknown` 先查记录，不据此反复点击最终按钮。

该分支首条实测上传手机主页、用户内容管理、原作页、对照图共4张截图，点击“提交投诉”一次，未遇验证码。页面跳转 `/pc/community/copyright/review` 并显示“提交成功，正在努力审核中”；另提示将在24小时内完成审核、通过系统通知告知结果。成功页未显示工单编号，据实保留编号为空，并保存成功页与实际提交时间。24小时只是当时页面提示，不承诺审核时效；审核结论与下架尚未验证。

## 状态与重试

最终动作前按平台+目标作品ID查现有候选和回执，避免别名、分享链接或重复搜索生成重复投诉。复用已覆盖当前目标、原作、材料与声明的授权；新增材料外发去向等实质变化只核对新增部分，不重新索取整批授权。

候选初始 `not_submitted`，最终点击前写 `submitting`。出现明确成功提示后记录 `submitted`、实际提交时间、回执截图与上传文件清单；平台显示投诉编号时据实记录，未显示则保留为空，不因没有编号重投。平台显示需要补正时记录 `needs_supplement`，不要创建重复投诉。明确失败可记 `failed`，保留原因，再据平台状态决定是否恢复为 `not_submitted`。

`report` 的当前 `submitted` 与累计 `historical_submitted` 分开理解：已提交后转补正仍保留有回执支持的历史提交事实。`active_todo` 也可能包含补正或结果不明对象，不表示这些对象可以重投；搜索中尚未登记的候选另由首批清单统计。

最终点击后无响应、连接中断、登录失效等可能已经送达，设 `unknown`，先查官方记录；未点击最终提交时仍记未提交，不因附件上传失败设为unknown。每次具体失败最多一次有依据的修复重试，重复同类失败后保存当前表单、已上传数量、未保存明细及缺项，交接或继续不受影响的工作，不循环点击。遇重复提示、风控、权限不足、对象消失或身份/权属争议停止该对象。

回执截图可能含姓名、联系方式；原件放 `00_private/receipts/`，普通 `07_receipts/` 仅存不含身份信息的版本或最小状态。隐私材料的原件始终保留，必要的裁剪或遮盖副本标为副本，不能覆盖取证原件。日志只记录编号、状态和相对路径，不记录证件内容或登录 token。

## 草稿文本框架

“本人为原作品《{已确认作品名}》的{实际权利身份}。原作链接为{URL}。被投诉内容{候选URL}中的{实际核实区间或逐点时刻}与原作{对应区间或时刻}在{具体已观察细节}相同/经{已核实变换}后对应，相关对照与权属材料见附件。{截图模式说明只核验所列点，不主张未观察中间帧。}本人确认未授权该账号在上述范围使用本作品，请平台核查并按规则处理。”

保留实际证据支持的句子；未得到用户真实性确认时不写“本人确认”。不主张未拥有的角色、音乐或第三方素材权利。
